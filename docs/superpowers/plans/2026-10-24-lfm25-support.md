# LFM2.5-24B-A2B Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add full-parity LFM2.5-24B-A2B support to the clean upstream TurboFieldfare 0.9.3 base, with Gemma 4 unchanged and Qwen 3.6 removed.

**Architecture:** The installed manifest carries a `ModelFamily` discriminator and optional architecture traits. A family-specific `ArchConfig` selects either the existing Gemma graph (`RealForwardRunner`) or a new `LFM2ForwardRunner` through `RunnerFactory`; tokenizers, chat rendering, decoders, and product surfaces dispatch on the same manifest family. Gemma keeps every existing default and its current history identity.

**Tech Stack:** Swift 6.2, Swift Testing, Metal compute kernels, MLX affine quantization, Foundation, the existing `Tokenizers`/`Hub` packages, and the existing `.gturbo` v1 container.

**Spec:** `docs/superpowers/specs/2026-10-24-lfm25-support-design.md`

## Global Constraints

- Branch `lfm25-support` is based on upstream `0.9.3` (`2e9ea50`). Do not copy source from `backup/qwen36-support-2026-10-24`.
- Gemma 4 26B-A4B remains the default model. Its graph, sampling defaults, context defaults, expert-cache default (16 slots), and history identity must not change.
- Family comes from the installed `manifest.json`; never from a compile-time selected model, a filename, or the app catalog.
- Preserve checkpoint numerics: embedding and tied lm-head are 6-bit; linear/conv/attention/expert weights 4-bit; router gate and expert bias F32; conv weights and norms BF16. Never requantize.
- No `.gturbo` format version bump. Every new manifest field is optional and absent Gemma manifests behave exactly as before.
- LFM defaults: 8,192-token context and 8 expert-cache slots. Gemma defaults stay 16 slots.
- LFM has no vision. Every image entry point must refuse before generation; never accept an image and answer as if it were absent.
- Reasoning text is discarded. The app may show “Thinking…”, but no reasoning text is stored in history or returned as visible content.
- Tests are Swift Testing (`@Suite`, `@Test`, `#expect`) and run through `Scripts/test.sh` (`swift test --no-parallel`).
- One app, CLI, server, or model-using test at a time. Do not start a second model process or terminate an existing one.
- Do not delete, reinstall, or modify `scratch/gemma4.gturbo`.
- Commit after every task. Do not commit model files or generated `.gturbo` directories.
- Hardware floor for model runs: macOS 26+, Swift 6.2+, sufficient disk, acceptable `memory_pressure -Q`, completed model directory, and no `TurboFieldfareServer|TurboFieldfareMac|TurboFieldfareDecodeService|TurboFieldfareCLI|TurboFieldfarePackageTests|swiftpm-testing-helper|mlx_lm|mlx-lm` process.

## Review Focus

1. A directory whose manifest claims `lfm2_moe` but is missing an LFM tensor, contains a dense-layer expert file, or carries Gemma constants must fail at load with a specific error before any Metal work. A reasonable person expects a clear refusal, not garbage tokens.
2. A tool-call body containing Python literals (`True`, `False`, `None`), nested JSON, escaped quotes, or several calls must parse exactly or fail the whole turn. A reasonable person expects no partial tool call and no silent argument loss.
3. A rewind deeper than 128 tokens after a tool loop must throw and leave both KV and conv state unchanged. A reasonable person expects the next turn either to work or to fail cleanly, never to continue from a corrupted cache.
4. An image attached to an LFM request in the CLI, server, app, or decode service must be refused with an explicit unsupported-image error before prefill. A reasonable person expects the model not to answer as though the image were absent.
5. Streaming a multi-byte UTF-8 character split across several LFM byte-level tokens must produce the exact character once, with no replacement characters or duplicated bytes.

- [ ] **Step 3: Implement 6-bit arithmetic**

Add to `Quantization.swift`:

```swift
public struct AffineSizes: Sendable, Equatable {
    public let packedColumns: Int
    public let weightBytes: UInt64
    public let auxBytes: UInt64
}

public enum AffineError: Error, Equatable {
    case unsupportedBits(Int)
    case columnsNotDivisible(columns: Int, groupSize: Int)
    case packedColumnsNotIntegral(columns: Int, bits: Int)
}

public static func affineSizes(rows: Int, columns: Int, bits: Int,
                               groupSize: Int) throws -> AffineSizes
```

Accept bits 4, 6, or 8. Require `groupSize > 0` and `columns % groupSize == 0`. Compute `packedColumns = columns * bits / 32` with an exact-division guard, `weightBytes = rows * packedColumns * 4`, and `auxBytes = rows * (columns / groupSize) * 2`. Payload alignment is 2 bytes for 4-bit, 4 bytes for 6-bit, and 1 byte for 8-bit: the INT8 GEMV kernel is byte-addressed, and Gemma's pinned resident layout places the 2-byte `layer_scalar` last in each layer, so later layer payloads are only guaranteed 2-byte aligned. Requiring 4 bytes for 8-bit would reject the pinned Gemma pack unless the planner changed `model_weights.bin` bytes and hashes.

Change `Model.affineSizes` to call the new helper and keep its existing error mapping.

In `RepackPlanner.logicalShape(forPackedSource:bits:)`, replace the last dimension with `source[last] * 32 / bits` and throw `RepackError.shapeMismatch` if it does not divide exactly. Keep the 4-bit result byte-identical.

- Per-generation scratch: hidden, normed, q/k/v, attention output, dense gate/up/act, router logits/indices/weights, expert activations, logits.

Decode:
1. 6-bit embedding lookup, no `sqrt(hidden)` scale.
2. For each layer: `operator_norm`; conv or attention; residual; `ffn_norm`; dense MLP or MoE; residual.
3. `embedding_norm`; 6-bit tied lm-head GEMV into FP16 logits.
4. `kv.advance()` after all layers write their K/V or conv state.

Conv layer:
- `in_proj` 4-bit GEMV to `[3*hidden]`; split B/C/x; `Bx = B*x`.
- `ShortConv.encodeDecode` over the two state rows; `C * conv`; `out_proj` 4-bit GEMV.
- Push `Bx` into the layer's history ring and shift the two-row current state.

Attention layer:
- `q/k/v` 4-bit GEMVs.
- `LFM2QKNormRoPE.encode` with 32 Q heads, 8 KV heads, head dim 64, position, theta 1e7, eps 1e-5.
- Write K/V into `kv.kSlot/vSlot`; run `Attention` with `maxQHeads: 32` and scale 0.125; `o_proj`.

Dense layers 0–1: `LFM2SharedExpert` with SiLU.

MoE layers 2–39: `LFM2Router` + stream 4 experts + `LFM2MoE`.

Prefill:
- Chunked by `PrefillRuntimeConfig.chunkTokens`.
- Embedding lookup for the chunk; standard RMSNorm; conv prefill with state; attention prefill with existing generic path; dense/MoE prefill.
- Write K/V for every position; update conv state to the last two `Bx` rows.
- Final row uses `embedding_norm` and the 6-bit head; return `.logitsWritten` or a greedy token according to `outputMode`.

Rewind:
- If `target <= 0`, `target > kv.position`, or `target < kv.highWaterPosition - convRewindLimit`, throw `PrefillError.prefillCursorMismatch` before touching either cache.
- Otherwise restore each conv layer’s ring cursor and two current rows from the ring, then `kv.rewind(to: target)`.
- `reset()` clears KV and conv ring; `prepareForContinuation(expectedPosition:)` validates both cursors.

`LFM2ChatRenderer` is a pure string renderer pinned to the fetched template:

- Empty `()` or `key=value` pairs separated by top-level commas.
- Values: single-quoted strings with `\\`, `\'`, `\n`, `\r`; JSON objects/arrays; numbers; `true`/`false`/`null`; Python `True`/`False`/`None`.
- Every name must be in `allowedTools`; otherwise `.unknownTool`.
- Convert all values to `JSONValue` and return `ParsedToolCall` with the supplied ID.
- No partial result on error.

- Render `incomingMessages` with `addGenerationPrompt: true` to `fullTokens`.
- Require `cachedMessages` to be a message prefix of `incomingMessages`.
- Require `fullTokens.count > cachedTokenIDs.count` and `fullTokens.prefix(cachedTokenIDs.count)` to equal `cachedTokenIDs`.
- Require the first suffix token to be `<|im_end|>` (124900) or `<|im_start|>` (124899). 124900 is the normal case: the KV excludes the stop token, so the next full-render token is the assistant turn's `<|im_end|>`.
